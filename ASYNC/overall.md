# Итоговая лекция: Асинхронный JavaScript и сетевые запросы

## 1. Асинхронность и Таймеры
JavaScript выполняет код в одном потоке, но благодаря **Event Loop** он может «откладывать» задачи на потом.
* **`setTimeout` / `setInterval`**: Базовые инструменты планирования. Помни, что рекурсивный `setTimeout` гибче, чем `setInterval`, так как гарантирует паузу между вызовами.
* **Промисы (Promises)**: Современный стандарт. Промис — это объект-обещание. Он всегда находится в одном из трех состояний: *Pending* (ожидание), *Fulfilled* (успех) или *Rejected* (ошибка).


### Работа с группой промисов
| Метод | Суть | Идеально для... |
| :--- | :--- | :--- |
| **`Promise.all()`** | Ждет **всех**. Упадет, если упал хотя бы один. | Загрузка всех данных для страницы. |
| **`Promise.race()`** | Ждет **первого** (любого). | Установка таймаута на запрос. |

---

## 2. Работа с данными и Сеть (Fetch & JSON)
**`fetch()`** — это основной метод для общения с сервером. Он всегда возвращает промис.
* **JSON**: Универсальный формат обмена данными. Мы используем `JSON.parse()` для чтения и `JSON.stringify()` для отправки данных.
* **URLSearchParams**: Избавляет от ручного парсинга строк типа `?id=1&tag=js`. Позволяет работать с параметрами URL как с объектом.


---

## 3. Оптимизация (Debounce & Throttle)
Когда событий слишком много (скролл, ввод в поиске), мы используем техники контроля частоты, чтобы не перегружать браузер и сервер.

| Техника | Аналогия | Главная цель |
| :--- | :--- | :--- |
| **Debounce** | **Лифт**: ждет паузу после последнего вошедшего. | Группировка событий в одно (конец ввода). |
| **Throttle** | **Кран**: капает с фиксированным ритмом. | Ограничение частоты выполнения (скролл). |

> **Важно:** Опция **`maxWait`** в дебаунсе — это «страховка», которая гарантирует вызов функции, даже если пауза так и не наступила.

## 🏗️ Финальный аккорд: Синтез всех знаний

Давай создадим код «Умного поиска». Он будет использовать `debounce` для экономии ресурсов, `fetch` для получения данных, `URLSearchParams` для формирования ссылки и `Promise.race` для защиты от слишком долгих ответов.

```javascript
// 1. Настраиваем параметры запроса через URLSearchParams
const getSearchUrl = (query) => {
    const params = new URLSearchParams({ q: query, limit: 5 });
    return `https://api.example.com/search?${params.toString()}`;
};

// 2. Функция запроса с защитой по времени (Promise.race)
async function fetchWithTimeout(url) {
    const timeout = new Promise((_, reject) => 
        setTimeout(() => reject(new Error('Сервер долго не отвечает')), 3000)
    );

    const request = fetch(url).then(res => {
        if (!res.ok) throw new Error('Ошибка сервера');
        return res.json(); // Парсим JSON
    });

    return Promise.race([request, timeout]);
}

// 3. Создаем дебаунс-версию поиска (Lodash style)
const performSearch = _.debounce(async (query) => {
    if (!query) return;

    try {
        console.log('Начинаю поиск...');
        const data = await fetchWithTimeout(getSearchUrl(query));
        console.log('Результаты:', data);
        // Здесь мы могли бы отрисовать данные в DOM
    } catch (err) {
        console.error('Поиск не удался:', err.message);
    }
}, 500, { maxWait: 2000 }); // maxWait гарантирует вызов раз в 2 секунды

// 4. Вешаем на инпут
document.querySelector('#search').addEventListener('input', (e) => {
    performSearch(e.target.value);
});
```
