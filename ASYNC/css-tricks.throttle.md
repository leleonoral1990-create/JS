Статья на **CSS-Tricks** — это, пожалуй, лучший ресурс, объясняющий механику **Throttle** «на пальцах». В то время как Debounce заставляет нас ждать конца бури, Throttle позволяет нам идти сквозь неё, но строго отмеренными шагами.

Давай разберем это через легендарную аналогию с «Краном», которую так любят авторы этой статьи.

---

## 1. Концепция: Кран с ограничителем

Представь, что у тебя есть кран с водой. События (`scroll`, `mousemove`) — это напор воды.
* **Без Throttle:** Ты открываешь кран на полную, и вода хлещет бесконтрольно (браузер пытается выполнить код 100 раз в секунду).
* **С Throttle:** Ты ставишь специальный клапан. Как бы сильно ты ни крутил ручку, клапан выпускает ровно одну каплю каждые $200$ мс.

**Суть:** Мы не ждем, пока пользователь перестанет крутить кран. Мы просто гарантируем, что вода будет капать с предсказуемым и безопасным для системы ритмом.



---

## 2. Почему это важно для UX?

В отличие от Debounce, который «замирает» до паузы, Throttle дает пользователю **немедленную обратную связь**. 

### Где это критично:
* **Индикаторы чтения (Scroll Progress):** Пользователь должен видеть, как полоска заполняется *в процессе* скролла, а не только когда он дочитал до конца.
* **Карты (Google Maps / Leaflet):** Когда мы перетаскиваем карту, мы хотим видеть плавное перемещение слоев, а не прыжок из точки А в точку Б после того, как отпустили мышь.
* **Игры:** Ограничение частоты выстрелов или проверки столкновений.

## 3. Реализация на чистом JavaScript (Vanilla JS)

Хотя Lodash удобен, понимание внутренней механики сделает тебя мастером. Вот как выглядит базовая версия Throttle:

```javascript
function throttle(func, limit) {
  let inThrottle; // Флаг: "сейчас мы в режиме ожидания?"
  
  return function(...args) {
    const context = this;
    
    if (!inThrottle) {
      func.apply(context, args); // Выполняем функцию сразу
      inThrottle = true;         // Захлопываем клапан
      
      setTimeout(() => {
        inThrottle = false;      // Открываем клапан через 'limit' мс
      }, limit);
    }
  };
}

// Использование:
const handleScroll = throttle(() => {
  console.log('Обновляем UI... Текущий скролл:', window.scrollY);
}, 200);

window.addEventListener('scroll', handleScroll);
```

## 4. Различия в поведении (Cheat Sheet)

Если ты сомневаешься, что выбрать, задай себе один вопрос: **«Мне нужно знать, что происходит В ПРОЦЕССЕ или только когда ВСЁ ЗАКОНЧИТСЯ?»**

| Ситуация | Выбор | Причина |
| :--- | :--- | :--- |
| Поиск с подсказками | **Debounce** | Не хотим спамить сервер на каждую букву. |
| Бесконечная лента | **Throttle** | Проверяем близость к подвалу каждые 100-200 мс. |
| Изменение размеров окна | **Debounce** | Пересчет сетки — дорогая операция, ждем финала. |
| Рисование в Canvas | **Throttle** | Нужно видеть линию под курсором в реальном времени. |

---

## 5. Нюанс: "Хвосты" (Trailing)

В статье на CSS-Tricks упоминается важная деталь: продвинутый Throttle (как в Lodash) умеет запоминать **последний** вызов. Если ты перестал двигать мышь на $150$-й миллисекунде, а лимит — $200$ мс, хорошая функция Throttle все равно выполнится еще один раз в конце, чтобы зафиксировать финальное состояние.

---

### Резюме
Throttle — это твой способ сказать браузеру: «Работай спокойно, не суетись». Это превращает хаотичный поток событий в ритмичную и предсказуемую работу.
