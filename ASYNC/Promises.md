# Промисы (Promises) в JavaScript

Ссылка ведет на учебный пример, посвященный **Промисам**. Если объекты — это данные, а функции — это действия, то **Промис** — это «обещание» того, что действие будет завершено в будущем. Это основной способ работы с асинхронным кодом в современном JS (например, при загрузке данных с сервера).

---

## 1. Концепция: «Обещание»

Представь, что ты заказываешь бургер в кафе:
1. Тебе дают **чек** (Промис). Сейчас бургера нет, он готовится.
2. Чек находится в состоянии **ожидания** (pending).
3. Через 5 минут возможны два варианта:
   * **Успех (fulfilled):** Бургер готов, ты его получаешь.
   * **Ошибка (rejected):** Продукты закончились, тебе возвращают деньги.



---

## 2. Состояния Промиса

У объекта `Promise` есть три внутренних состояния, которые нельзя изменить напрямую:

| Состояние | Описание | Результат (`value`) |
| :--- | :--- | :--- |
| **`pending`** | Ожидание выполнения (начальное). | `undefined` |
| **`fulfilled`** | Операция завершена успешно. | Результат операции. |
| **`rejected`** | Произошла ошибка. | Объект ошибки (reason). |

---

## 3. Как создать Промис

Промис создается через конструктор `new Promise`, который принимает функцию-исполнитель (executor). Эта функция получает два аргумента: `resolve` (для успеха) и `reject` (для ошибки).

```javascript
const myPromise = new Promise((resolve, reject) => {
    const isSuccess = true;

    setTimeout(() => {
        if (isSuccess) {
            resolve("Данные получены! ✅");
        } else {
            reject("Ошибка сети! ❌");
        }
    }, 2000);
});
```

---

## 4. Как работать с результатом (Consumption)

Чтобы «подписаться» на результат промиса, используются методы `.then()`, `.catch()` и `.finally()`.

```javascript
myPromise
    .then((data) => {
        // Сработает, если вызван resolve
        console.log(data); 
    })
    .catch((error) => {
        // Сработает, если вызван reject
        console.error(error);
    })
    .finally(() => {
        // Сработает В ЛЮБОМ СЛУЧАЕ (например, чтобы скрыть индикатор загрузки)
        console.log("Завершено");
    });
```



---

## 5. Цепочки промисов (Chaining)

Главная сила промисов в том, что результат одного `.then()` можно передать в следующий. Это избавляет нас от «адских колбэков» (Callback Hell).

```javascript
fetch('https://api.example.com/user/1')
    .then(response => response.json()) // Превращаем ответ в объект
    .then(user => user.id)             // Берем ID пользователя
    .then(id => console.log(id))       // Выводим ID
    .catch(err => console.error(err)); // Ловим ошибку на любом этапе
```

---

## 6. Статические методы (Работа с группой)

Иногда нужно запустить несколько процессов одновременно.

| Метод | Поведение |
| :--- | :--- |
| **`Promise.all([...])`** | Ждет выполнения **всех** промисов. Если хоть один упадет — упадет всё. |
| **`Promise.allSettled([...])`** | Ждет завершения всех, неважно — успешно или с ошибкой. |
| **`Promise.race([...])`** | Возвращает результат того промиса, который выполнился **первым** (гонка). |
| **`Promise.any([...])`** | Возвращает результат первого **успешного** промиса. |

---

## Почему это важно?
До появления промисов асинхронный код выглядел как бесконечные вложенные функции, в которых было невозможно разобраться. Промисы сделали код линейным и понятным. Современный синтаксис `async/await`, который ты наверняка встретишь позже, — это просто «красивая обертка» над этими самыми промисами.
