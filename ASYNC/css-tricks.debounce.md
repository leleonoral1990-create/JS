## 1. Проблема: «Слишком много событий»

Браузер — существо очень старательное. Если ты скроллишь страницу, он может генерировать событие `scroll` до **100 раз в секунду**. Если на каждое такое событие ты повесишь пересчет геометрии или запрос к серверу, интерфейс просто «умрет».

**Решение:** Контроль частоты (Rate Limiting).



---

## 2. Debounce (Группировка)

**Суть:** Мы говорим функции: «Не выполняйся, пока не наступит пауза». Если события идут одно за другим, мы каждый раз сбрасываем таймер и ждем заново.

> **Аналогия с лифтом:**
> Представь лифт в торговом центре. Двери начинают закрываться, но заходит человек — двери открываются снова. Заходит следующий — опять открываются. Лифт не поедет, пока не наступит пауза и никто не будет пытаться зайти в течение пары секунд.

### Когда использовать:
* **Автодополнение (Search):** Не отправлять запрос, пока пользователь не допечатал слово.
* **Изменение размера окна (`resize`):** Пересчитывать сетку только тогда, когда пользователь отпустил край окна и закончил менять размер.
* **Валидация полей:** Проверять правильность Email только после того, как ввод прекратился.

---

## 3. Throttle (Замедление)

**Суть:** Мы гарантируем, что функция будет выполняться **не чаще** чем один раз в указанный период времени. Даже если событий тысячи, выполнение будет идти «порциями» по расписанию.

> **Аналогия с краном:**
> Как бы сильно ты ни открывал кран, если там стоит ограничитель, вода будет капать с четким ритмом — одна капля в секунду. Ты не можешь заставить её течь быстрее.

### Когда использовать:
* **Бесконечный скролл:** Проверять, пора ли подгружать новые посты, каждые 200 мс.
* **Индикаторы прокрутки:** Обновлять положение прогресс-бара чтения с фиксированным ритмом.
* **Игровые циклы:** Обработка движений персонажа или стрельбы.

---

## 4. Сравнение «лицом к лицу»

| Характеристика | Debounce | Throttle |
| :--- | :--- | :--- |
| **Главная цель** | Сгруппировать серию событий в **одно**. | Ограничить частоту выполнения до **X** раз в секунду. |
| **Когда сработает?** | В самом конце (после паузы). | Регулярно в процессе потока событий. |
| **Идеально для...** | Действий, которые должны случиться «по факту завершения». | Действий, которые должны обновляться «в процессе», но плавно. |

## 5. Как это выглядит "под капотом" (Vanilla JS)

Чтобы не зависеть от библиотек вроде Lodash, полезно понимать, как написать простейший `debounce` самому.

### Реализация Debounce:
```javascript
function debounce(func, delay) {
  let timeout;
  return function(...args) {
    clearTimeout(timeout); // Сбрасываем старый таймер
    timeout = setTimeout(() => func.apply(this, args), delay); // Запускаем новый
  };
}

// Использование:
const handleResize = debounce(() => {
  console.log('Размер изменен! Пересчитываем макет...');
}, 300);

window.addEventListener('resize', handleResize);
```

## Leading vs Trailing (Крайние случаи)

В статье упоминается, что и у `debounce`, и у `throttle` могут быть разные режимы:
* **Leading (Первый):** Функция срабатывает мгновенно при первом событии, а потом игнорирует остальные (лифт уезжает сразу с первым вошедшим, а остальные ждут).
* **Trailing (Последний):** Функция срабатывает только после паузы (стандартное поведение).

### Резюме
Если тебе нужно, чтобы действие произошло **один раз в самом конце** — бери `debounce`.
Если тебе нужно, чтобы действие происходило **постоянно, но по чуть-чуть** — бери `throttle`.
